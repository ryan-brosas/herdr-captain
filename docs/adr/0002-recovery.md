# ADR-0002: Worker survival, holder-process lease, commit log, and readback recovery

**Status:** PROPOSED (separates accepted user direction from proposed fencing, storage, and recovery mechanisms; design draft, not implementation approval).
**Date:** 2026-11-27.

## Context

`hc` `0.1.22` child terminals end with their parent unless launched with `--outlive-parent`, `hc run` can fail after launch during registry save, `hc send` can report ambiguity, and `hc keep` replaces a dead program with a bare shell (`hc` `0.1.22` `--skill`). Meanwhile, `/reload` creates a new extension instance (`pi-fabric` `0.140.1`, `docs/providers.md`, host policy section). Under Pi (`@earendil-works/pi-coding-agent` `1.6.1`), each reload evaluates a new module in the same Bun process sharing `globalThis`. In simulated reloads, a new module must revoke and close the prior holder through `globalThis`. Real Pi `/reload` wiring remains untested ([P2, runtime environment](../probes/p2.md#runtime-and-host-environment); [check notes](../probes/p2.md#check-by-check-notes)). Concurrent Captains can open linked worktrees of the same clone. Multi-file rename sequences (`state.json` plus separate event files) lack a crash-atomic transaction boundary.

## Decision

### Accepted user direction

1. Enforce one Captain execution owner per project, including across linked worktrees of the same clone.
2. When the Captain is absent, already-running workers may finish their authorized assignment, while new dispatches, follow-up turns, replacement launches, and merges stop until the Captain returns. No replacement Captain or daemon runs.
3. On return, reconcile automatically from observed state and evidence, then resume at the last verified step. Preserve branches and work. Never blindly replay uncertain external actions; escalate unresolvable ambiguity.
4. Keep `--outlive-parent` semantics explicit, and never treat an OS crash or an `hc keep` restored shell as resumed work.

### Proposed technical mechanism

1. **Canonical project key:** Set `projectKey` to the first 16 hex characters of `sha256(realpath(git rev-parse --git-common-dir))` and use `<projectKey>` alone as the state directory name. Version 1 acquires the owner lease first, writes `project.json` once, refuses unborn repos and mismatches, and warns on origin drift. On first publication, a best-effort scan checks shared root commits and missing old paths (ignoring origin) and refuses a detectable moved clone with `identity_relocated`. Version 1 has no rebind; recovery stops Captains and workers and moves the named old directories out by hand to start a fresh ledger ([architecture.md, section 3](../architecture.md#3-project-identity-and-state-root)).
2. **One lease mechanism (holder process):** Start `flock --exclusive --nonblocking --no-fork --conflict-exit-code 200 <stateRoot>/owner.lock <holder>` with a non-forking holder (`exec`). This requires Linux local filesystems, `/proc`, and a `util-linux` `flock` with those flags. Probe P2 tested it on one `Linux x64` host with `bun 1.4.0` and `flock from util-linux 2.42.4`. One process holds the lock, prints one ready line, and blocks reading stdin. Parent death closes that pipe so the holder exits and releases the lock. Exit `200` fails closed with `owner_conflict`, separate from startup errors, and code never unlinks `owner.lock`. Bump `owner.json` `epoch` only after the ready line. If `owner.json` read, validation, or write fails, close stdin and await holder exit before throwing. Run writes and effects in one serialized queue per `projectKey`. Before each write and effect, check `revoked === false`, `owner.json.epoch === localEpoch`, and holder liveness. Read holder liveness synchronously from `/proc/<holderPid>/stat`: reject `Z`, `X`, and `x`, and check `starttime`. Do not rely on async exit callbacks or `kill(pid, 0)`. On controlled revocation, set `revoked = true` first and drain the queue (`lease_revoked`). Then close stdin and await holder exit, with a bounded `SIGKILL` fallback, before revocation resolves. If the holder exits unexpectedly, the lock is already free and the synchronous liveness check stops the next effect. For reloads, store `revokeAndClose(): Promise<void>` on a `Symbol.for(...)` map on `globalThis`, await it before acquiring, and compare-and-delete on exit. Forbid forwarding numeric file descriptors or holder streams in child `stdio`. Keep a `/proc` and surviving-child test in Slice S1. Test any launch API other than `node:child_process.spawn` before adopting it ([P2, verdicts](../probes/p2.md#verdicts-for-section-5-rules-a-to-f); [runtime environment](../probes/p2.md#runtime-and-host-environment)).
3. **One append-only commit log per ticket:** Replace mutable snapshots and separate event logs with `tickets/<issue>/log/<seq6>.json` created exclusively (`temp -> fsync -> hard-link -> unlink -> dir fsync`), with content-addressed write-once artifacts written first. Fold the log through the policy kernel on every load; quarantine any hash-chain, schema, artifact-hash, or law violation to `quarantined`.
4. **Effect ordering and strict non-delivery proof:** Run `hc run` and `hc send` inside the serialized queue as `intent -> effect -> receipt`. Definite `not_delivered` exists **only** when `hc run` returns an error with no terminal address and that receipt is recorded. After a crash before receipt or a registry save failure, look up the terminal by deterministic name. Terminal names allow `1-32` characters from `a-z 0-9 - _ .` and are unique among live terminals. The draft `<projectKey>-<issue>-<role>-<attemptId>` can exceed 32 characters, so Slice 3 must use a shortened deterministic format (for example `<projectKey8>-<issue>-<roleCode>-<attemptId>`). If found, bind the terminal and inspect `first_message`. `hc get` keeps `first_message` only when it was not sent (`sent: false`), so readback cannot rely on seeing `sent: true` there. Stay `uncertain` and escalate without launching a second terminal. If not found, keep the attempt `uncertain` and escalate without launching a replacement. Never blind-resend ambiguous sends ([P3, Behaviour 2](../probes/p3.md#behaviour-2-first_messagesent-for-ready-and-late-ready-programs); [Behaviour 3](../probes/p3.md#behaviour-3-deterministic-name-lookup-after-forgetting-the-address)).
5. **Separate worker write ownership and post-merge closeout:** Derive active writer ownership from the commit log's open `implementer` attempt so Captain absence never clears it. Keep `merged` distinct from `closed` so closeout retries never reopen merge gates.

## Alternatives considered

- **Folder basename plus hash in the directory key:** Rejected. Linked worktrees with different folder names would acquire separate locks for one repository.
- **Read-epoch plus atomic rename, or TTL lease takeover:** Rejected. Atomic rename is not mutual exclusion, and TTL takeover risks split-brain when a slow Captain still holds in-flight calls.
- **`state.json` checkpoint plus separate `events/` and `attempt.json` files:** Rejected. Multiple renames are not crash-atomic and can double-consume evidence or lose advancement on replay.
- **Treating an absent terminal on readback as `not_delivered`:** Rejected. After a registry save failure, absence from the registry does not prove the process never started and can spawn a duplicate writer.
- **Enabling `hc keep` on worker launches:** Rejected. Replaces a dead process with a bare shell rather than resuming the task.

## Consequences

- **Benefits:** One crash-atomic commit boundary per transition, shared locking across linked worktrees, explicit fencing across `/reload` and withdrawal, and zero duplicate launches from registry absence.
- **Costs and unproved items:** Version 1 runs only on Linux local filesystems with `/proc`. It also needs `util-linux` `flock` with `--no-fork` and `--conflict-exit-code`. Probe P2 tested the refined lease on one `Linux x64` host under `bun 1.4.0`. P2 did not test real Pi `/reload` wiring, `Bun.spawn`, or explicit descriptor forwarding ([P2, scope limits](../probes/p2.md#scope-limits-and-unproven-items)). Probe P3 observed `hc` `0.1.22` in live use without a scratch core. P3 confirmed `--outlive-parent` on clean parent exit and name lookups under the `1-32` character limit. It also showed unsent-only `first_message` retention on `hc get`, cropped `hc read` returning `complete: true`, and `hc wait` exiting `0` on timeout. In `hc get`, `status` is an object or `null`, and `turn` moves only when leaving `working`. Noted live launches also hit worktree trust dialogs (`first_message.sent: false`) and mouse escapes on full-screen history reads. P3 did not observe parent `SIGKILL` or OS crash, `hc keep`, `RunResult` `first_message.sent: true`, or late-ready programs. Send-to-turn attribution, bare `hc wait --children`, dead-parent replies, `hc label` filtering, and finished full-screen agent reads also stayed unobserved ([P3, summary](../probes/p3.md#summary-of-behaviours-1-to-7); [not observed](../probes/p3.md#not-observed)). No exactly-once external effect guarantee is claimed.
- **No rebind in version 1:** Rebind is left out so version 1 keeps one clone at one path with a write-once `project.json`, with no decision files or ancestry list. Recovery from a moved clone is done by hand ([architecture.md, section 3](../architecture.md#3-project-identity-and-state-root)).

## Revisit conditions

Probes P2 and P3 completed and exposed the host and `hc` limits recorded in this ADR. Captain and user should revisit this ADR if Captain runs on macOS, Windows, or network filesystems. Also revisit it if Linux `/proc` or the required `flock` flags are unavailable. Revisit it if `hc` adds native idempotency tokens, an `attemptId` field (issue `#27`), or leases. Check again if real Pi `/reload` testing, another launch API, or any `Not observed` `hc` behaviour breaks these assumptions ([P2, scope limits](../probes/p2.md#scope-limits-and-unproven-items); [P3, not observed](../probes/p3.md#not-observed)).
