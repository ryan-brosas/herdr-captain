# Probe P2: Owner lease lifecycle faults

**Status:** COMPLETE. The holder-process owner lease in [architecture.md](../architecture.md) section 5 works on Linux under Bun. Rules **(a)**, **(b)**, **(d)**, and **(e)** each need a small design change before Slice 1 builds on them.

Terms follow [CONTEXT.md](../../CONTEXT.md). Related decisions live in [0002-recovery.md](../adr/0002-recovery.md).

## Runtime and host environment

How `pi` starts on this host was checked directly rather than assumed:

- The `pi` launcher runs `bun --no-env-file <pi-bin> "$@"`.
- The installed Pi package (`@earendil-works/pi-coding-agent` `1.6.1`) loads TypeScript extensions in-process via `jiti` with `moduleCache: false`. Each `/reload` evaluates a new module instance inside the same Bun process while sharing `globalThis`.
- Probe runtime and host tools:
  - JavaScript runtime: `bun 1.4.0` (standard library `node:*` APIs only, zero external dependencies)
  - Lock binary: `flock from util-linux 2.42.4`
  - Git binary: `git version 2.56.0`
  - Kernel: `Linux 7.2.15-1-omarchy x64`

Every test wrote only inside `<scratch>` folders made with `mktemp` under `/tmp` and removed on exit.

## Probe implementation

- [probes/p2/lease.mjs](../../probes/p2/lease.mjs): owner lease holder, atomic `owner.json` fencing epoch, per-project serialized queue, revocation drain, process-global `Symbol.for(...)` map, and `git rev-parse --git-common-dir` key resolver.
- [probes/p2/owner-worker.mjs](../../probes/p2/owner-worker.mjs): separate Bun worker process for multi-process contention, `SIGKILL`, and post-acquisition child checks.
- [probes/p2/run.mjs](../../probes/p2/run.mjs): runner script for checks 1 to 6 using real processes, real `flock`, and no sleep synchronization. It exits non-zero if any check fails.
- [probes/p2/diagnose-design-gaps.mjs](../../probes/p2/diagnose-design-gaps.mjs): runnable checks that reproduce the three design gaps found in section 5 (`--no-fork`, `--conflict-exit-code`, and awaiting holder exit on close).

## Check-by-check notes

1. **Check 1 (Second owner conflict):** A second Bun process failed right away with `owner_conflict` (exit `2`). The `owner.json` SHA-256, inode, and mtime did not change. Owner 1 kept its lease and finished a queued write afterward.
2. **Check 2 (`SIGKILL` release timing):** Sending `SIGKILL` to owner 1 closed its stdin descriptor and caused holder 1 to exit. Kernel lock release took `1.93ms`, timed by a blocking `flock --exclusive --timeout 5` wait with no sleep polling. In four runs, kernel release took `1.56ms` to `1.94ms`. Owner 2 then acquired on its first `--nonblocking` try (`25.19ms` total including Bun startup), bumped `owner.json` from epoch `1` to `2`, and blocked owner 3 with `owner_conflict`. A restarted owner arriving during that ~2ms teardown window fails closed with `owner_conflict` rather than stealing the lease.
3. **Check 3 (Simulated reload in one process):** **Simulated reload only; real Pi `/reload` is another ticket (Probe P1).** Bun `1.4.0` strips query strings from `file://` ESM URLs, so `import("./lease.mjs?reload=2")` returns the cached module. The probe copies `lease.mjs` to distinct `<scratch>` paths to force fresh module evaluations. It confirms distinct `MODULE_INSTANCE_ID` values and distinct `LeaseError` constructors. All 12 consecutive reloads handed off through the `Symbol.for(...)` registry on `globalThis` with no sleeps. Prior holders exited each time, and stale calls on instance 1 rejected with `lease_revoked`.
4. **Check 4 (Withdrawal with queued work):** Item 0 ran its authorized write, then paused at a promise barrier before its effect check while items 1 to 3 queued behind it. Calling `revoke()` set `revoked = true` first, before drain began. While paused, an external process still hit `owner_conflict`, showing the holder kept the lock during drain. Opening the barrier rejected item 0's effect and items 1 to 4 (including item 4 queued after `revoke()`) with `lease_revoked`. Neither `forbidden-write.marker` nor `forbidden-effect.marker` appeared. External holder `SIGKILL` and `owner.json` epoch drift also failed closed with `lease_revoked`.
5. **Check 5 (Post-acquisition child non-inheritance):** `/proc/self/fdinfo` in owner 1 showed Bun opened holder stdio as Unix `socketpair` descriptors with `O_CLOEXEC` (`flags=02004002`). A detached `sleep 60` child started after acquisition had only `/dev/null` on fds 0 to 2. After `SIGKILL` of owner 1, the kernel lock released in `1.61ms` and owner 2 acquired epoch `2` while the detached child stayed alive.
6. **Check 6 (Linked worktree contention):** Two differently named linked worktrees (`wt-alpha` and `completely-different-name`), a symlink (`wt-beta-symlink`), and `main-clone` all resolved `realpath(git rev-parse --git-common-dir)` to the same 16-hex `projectKey` (`689a8f52ff405941`). They contended for one owner lease. A separate clone of the same repository hashed to `424fac3bd1aef459` and acquired on its own.

## Verdicts for section 5 rules (a) to (f)

| Rule | Verdict | Smallest design change |
|---|---|---|
| **(a) No stealing** | Needs a design change | Pass `--nonblocking` and `--conflict-exit-code 200` to `flock`, and forbid unlinking `owner.lock`. |
| **(b) Fencing epoch** | Needs a design change | Pass `--no-fork` (`-F`) to `flock` with a non-forking holder (`exec`), and close plus await holder exit on `owner.json` failure. |
| **(c) Serialized queue** | Holds | None to the rule. On Linux, check `/proc/<holderPid>/stat` (non-zombie) for holder liveness instead of `kill(pid, 0)` alone. |
| **(d) Revocation drain** | Needs a design change | After closing holder stdin, await holder process exit (with a bounded `SIGKILL` fallback) before resolving revocation. |
| **(e) Reload cleanup** | Needs a design change | Store a revocation handle (`revokeAndClose(): Promise<void>`) in the `Symbol.for(...)` global map, await it before acquiring, and compare-and-delete on exit. |
| **(f) Non-inheritance** | Holds | None to the rule. Because JS relies on Bun to set `O_CLOEXEC` on child stdio, keep a `/proc` and surviving-child check in Slice 1. |

### Detailed rule rationale

- **(a) No stealing (needs a design change):** Kernel `flock` exclusion held in every cross-process and worktree check. Without `--conflict-exit-code`, however, `flock` exits `1` on lock conflict. That collides with a holder process that exits `1` before printing its ready line (`DIAG [gap-2]`). Passing `--conflict-exit-code 200` (outside `sysexits` 64 to 78 and shell codes 126 to 128) and `--nonblocking` separates `owner_conflict` from startup errors. Code must also never unlink `owner.lock` on release because unlinking splits the path onto a second inode.
- **(b) Fencing epoch (needs a design change):** Ready-line order, `projectKey` checks, monotonic `epoch`, and `temp -> fsync -> rename` plus directory `fsync` all worked under Bun `1.4.0`. Without `--no-fork`, `flock` forks `<holder>` so two processes hold `owner.lock`, and `child.pid` is `flock` instead of `<holder>`. Sending `SIGKILL` to `flock` while stdin stays open leaves `<holder>` alive as an orphan still holding the lock (`DIAG [gap-1]`). Passing `--no-fork` with a non-forking holder (`sh -c 'printf "ready\n"; exec cat >/dev/null'`) keeps one PID (`child.pid === holderPid`). If `owner.json` validation or write fails after the ready line, acquire must close stdin and await holder exit before throwing.
- **(c) Serialized queue (holds):** FIFO order and checks before each write and each effect (`revoked === false`, holder alive, `owner.json.epoch === localEpoch`) failed closed on withdrawal, external holder `SIGKILL`, and `owner.json` epoch drift (Check 4). On Linux, `kill(pid, 0)` still succeeds on an unreaped zombie whose descriptors are already closed. Implementations should read `/proc/<holderPid>/stat` and reject `Z` and `X` states.
- **(d) Revocation drain (needs a design change):** Setting `revoked = true` first and draining queued work before closing stdin blocked every post-revocation write and effect while keeping `owner.lock` held during drain (Check 4). Closing stdin does not free the lock right away. Closing stdin without awaiting holder exit raced immediate re-acquisition and hit `owner_conflict` in `3/40` back-to-back handoffs, versus `0/40` when awaiting holder exit with no sleep (`DIAG [gap-3]`). Revocation must await holder exit (with a bounded `SIGKILL` fallback, safe once `--no-fork` is used) before resolving.
- **(e) Reload cleanup (needs a design change):** A `Symbol.for(...)` map on `globalThis` bridged separate module evaluations cleanly through 12 consecutive simulated reloads (Check 3). Storing only a raw holder pipe or child handle is not enough. Reload cleanup must set the old instance's `revoked` flag, drain its queue, close stdin, and await prior holder exit before starting a new `flock`. That avoids both overlapping writes and the `gap-3` close-vs-acquire race. Cleanup on exit must compare-and-delete (`if (map.get(projectKey) === entry) map.delete(projectKey)`) so a late exit callback cannot erase the new instance's entry. Real Pi `/reload` remains unproven here and belongs to Probe P1.
- **(f) Non-inheritance (holds):** Under `bun 1.4.0`, `node:child_process.spawn` creates holder stdio as `O_CLOEXEC` Unix `socketpair` descriptors (`flags=02004002`). Detached children started after acquisition inherit none of them, and `SIGKILL` of the owner releases the lease while the child stays alive (Check 5). Because JS standard library code relies on the runtime rather than calling `pipe2(O_CLOEXEC)` directly, Slice 1 tests should keep this check to catch any runtime regression.
