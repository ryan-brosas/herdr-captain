# Probe P4: `gdp-wired` compiled kernel packaging

**Date:** 2026-11-27
**Status:** PASSED (Checks 1 to 6 passed; ADR-0003 verdict below)
**Scope:** Test [ADR-0003](../adr/0003-deterministic-policy.md) and [docs/architecture.md](../architecture.md) section 6 using a standalone package in [probes/p4/](../../probes/p4/package.json).

## Verdict on ADR-0003

**Core mechanism holds; ADR-0003 needs two named updates before Slice 2.**

`gdp-wired` `0.62.0` proves the cut-down attempt budget rule over every step from any state (`{ from: 'any' }`), returning `proven: true`, `checked: true`, and no `assumes`. A `<=` guard mutant fails with a concrete `sat` counterexample. Compiling the rule twice with `compileJs` gives byte-identical output. The shipped artifact matches `rule.interpreter()` on all sampled inputs and boundaries, and runs offline with zero runtime dependencies.

### Trust boundary

Each check covers a distinct layer, and `checked: true` does **not** certify the shipped JavaScript bytes:

- **Kernel proof (`proveSteps(..., { from: 'any' })`, `proven: true, checked: true`):** certifies the `gdp-wired` rule's abstract machine against its state laws and step laws from any valid state. It does not certify `compileJs`, any packaging pass over compiler output, or the shipped JavaScript bytes.
- **Double compile and manifest hashes (Check 1):** bind the source inputs and pinned `gdp-wired@0.62.0` toolchain deterministically to the emitted bytes, and detect post-emit tampering. They do not prove that a packaging step preserved rule semantics.
- **Equivalence check (Check 4):** samples concrete behavior of `generated/attempt-budget.js` against `rule.interpreter()` (`2403` steps on counterexamples, boundary caps, reloaded states, depth-4 exhaustive traces, and `6` `RangeError` cases).
- **Packaging transform ([probes/p4/scripts/compile-kernel.mjs](../../probes/p4/scripts/compile-kernel.mjs)):** parsing `compileJs` output, pruning unused `$wordDivisionValue` and `fork`, and wrapping `{ init, step }` sit outside the kernel proof. Only equivalence sampling (Check 4) and direct file inspection cover that step. Inspection shows that the retained `$n`, `$x`, `init`, and `step` definitions match raw `compileJs` output verbatim.

### Requested updates to ADR-0003 before Slice 2

1. **Require the `gdp-wired` MIT notice beside `generated/`:** `compileJs` embeds runtime guard helpers (`$n`, `$x` from `dist/core/codegen.js:140-141`, and other helpers from lines `139-164` when needed; plus `$wordDivisionValue` from `dist/kernel/word-division.js:44-82` if unpruned). All emitted helpers are MIT-licensed (`Copyright (c) 2026 Tom X Nguyen`, `LICENSE:1-21`). MIT lines `12-13` require keeping the copyright notice and permission notice in copies or substantial portions. Add a requirement to ship `THIRD_PARTY_NOTICES.md` (as [probes/p4/THIRD_PARTY_NOTICES.md](../../probes/p4/THIRD_PARTY_NOTICES.md) does) alongside `generated/`.
2. **Record the `gdp-wired/emit` revisit check and emitter choice:** ADR-0003 lists an official zero-dependency runtime bundle as a revisit condition. `gdp-wired` `0.62.0` ships `gdp-wired/emit` (`emitRule`, `dist/core/emit.js:1232`), which outputs zero-dependency TypeScript (`.ts`) with named types and proof comments. Unlike `compileJs`, `emitRule` emits `.ts` (needing a build or type-stripping step) and omitted `$x` safe-integer overflow wrappers on additions in `step` for this rule. ADR-0003 should record whether Slice 2 keeps `compileJs` for plain ESM `.js` + `.d.ts` + `manifest.json` (and whether it ships raw or pruned output, below) or adopts `emitRule` plus dev-time `tsc`.

### Optional packaging choice (left to ADR-0003)

`gdp-wired` `0.62.0` `compileJs` (`dist/core/machine.js:1218`) unconditionally embeds `const $wordDivisionValue = ${wordDivisionValue.toString()};` (`dist/kernel/word-division.js:44-82`) even when a rule never uses fixed-width word division. That helper is self-contained, MIT-licensed, and unreferenced.

- **Simpler alternative (raw output):** ship raw `compileJs` output as emitted. In a scratch ESM check, raw `compileJs` output exported `init`, `step`, and `fork`, loaded directly in Node, and matched `rule.interpreter()` without custom parsing or helper removal. This keeps the trust boundary smaller.
- **Optional pruning:** parse `compileJs` output and drop unreferenced helpers (as [probes/p4/scripts/compile-kernel.mjs](../../probes/p4/scripts/compile-kernel.mjs) and `pi-fabric` `0.140.1` `scripts/verified-kernels.ts:96-138` do). Pruning shrinks the file, but adds a custom transformation step to the trust boundary covered only by sampling and inspection.

Whether Slice 2 ships raw `compileJs` output or adds an optional pruning pass is a choice for ADR-0003, not a required change from this probe.

### Precedent observation (`pi-fabric` `0.140.1` installed package)

ADR-0003 cites the `pi-fabric` source repository at release `0.139.0` (commit `0aaad42685a4dbe49194ee14a9a2f82caf6ef3b0`, `scripts/verified-kernel-worker.ts:18,27,37-55` and `scripts/verified-kernels.ts:1-132`). This probe did not read the `0.139.0` source repository.

In the installed `pi-fabric` `0.140.1` npm package, `package.json` `files` ships `dist/`, `skillsets/`, `docs/`, `README.md`, `LICENSE`, `THIRD_PARTY_NOTICES.md`, `proofs/`, and `scripts/verified-kernels.ts`. This probe observed `scripts/verified-kernels.ts` (159 lines), `proofs/kernel.ts` (44 lines), and `THIRD_PARTY_NOTICES.md:11-17`. `scripts/verified-kernel-worker.ts` and `scripts/verified-kernel-pool.ts` are absent from the installed `0.140.1` npm package; that absence does not contradict ADR-0003's citation of the `0.139.0` source commit, so no ADR-0003 change is requested here.

Confirmed as written: `compileJs` validates `params` and `input` via `$n(...)`, enforces rule assumptions (`event < 3`), and guards arithmetic outputs via `$x(...)`, but does not re-validate `state.scalars` on entry. That confirms ADR-0003's reload contract: validate schema, hash chain, natural-number bounds, and every state law when folding the execution ledger on load.

## How network unavailability was enforced (Check 5)

Check 5 created a Linux user and network namespace with `unshare -rn` (`util-linux` `2.42.4`). Inside that namespace, no external interface exists and `lo` is `DOWN` (`os.networkInterfaces()` returns `{}`). The child process ran from `<scratch>/runtime` with only two copied files (`attempt-budget.js` and `run-compiled-offline.mjs`), no `package.json`, no `node_modules`, `NODE_PATH=""`, and an empty `HOME` and npm cache path under `<scratch>`.

Before importing the compiled artifact, `run-compiled-offline.mjs` proved both conditions directly:

- **Network unavailable:** `os.networkInterfaces()` had `0` non-internal interfaces, a raw TCP connect to `1.1.1.1:443` failed with `ENETUNREACH`, and `fetch('https://registry.npmjs.org/gdp-wired')` failed with `EADDRNOTAVAIL`. (Note: `dns.lookup` via `nss-resolve` can still query a host `systemd-resolved` Unix socket when only the network namespace is unshared; raw TCP and HTTPS `fetch` prove actual packet egress is blocked.)
- **Zero runtime install:** `await import('gdp-wired')` failed with `ERR_MODULE_NOT_FOUND`.
